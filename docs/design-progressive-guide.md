# 渐进式实验引导系统 — 设计方案

> **目标:** 将12个实验从"一次性摊开的说明书"变为"逐步解锁的探索旅程"，让学生在每一步先理解原理再动手操作。

---

## 一、核心理念

### 当前问题
- 学生打开 README 看到全部任务，信息过载
- 先做后想，容易变成"机械执行命令"
- 没有进度感知，不知道自己在哪一步
- 卡住了没有提示，只能问老师

### 设计三原则
1. **WHY → DO → CHECK** — 每步先解释原理，再给操作，然后自我验证
2. **一次只看一步** — 学生看不到后面的步骤，减少焦虑
3. **自己掌控节奏** — 按回车继续，需要提示按 `h`，完全卡住才看 `s`

## 三、两个入口

系统有两个完全独立的入口脚本：

```
学生:   ./student.sh    → 进入实验引导系统
教师:   ./teacher.sh    → 进入教学管理面板
```

学生看不到教师入口的功能，教师可以随时切换到学生视角演示。

---

- **回顾**已完成的实验（输入编号如 `01`）

- 跳过未解锁的实验
- 查看教师配置
- 修改进度

进入实验后就是之前设计的分步引导界面（WHY→DO→CHECK），按 `h` 获取提示。

教师运行：

```bash
cd ~/cyber-practice
./teacher.sh
```

```
║  │ kali     │ 4/12 31% │ lab04    │ 1.2h  │ ║
║  │ student2 │ 2/12 15% │ lab02    │ 0.5h  │ ║
║  └──────────┴──────────┴──────────┴───────┘ ║
║                                              ║
║  🛠️ 管理操作                                  ║
║  [1] 系统配置 (答案可见性/解锁模式/提示等级)   ║
║  [2] 学生进度管理 (重置/解锁/查看详情)         ║
║  [3] 快速演示 (以学生视角打开任意实验)         ║
║  [4] 教学统计 (各步骤耗时/常见卡点)            ║
║  [5] 一键重置所有学生进度                      ║
║  [6] 进入学生模式 (亲自体验)                   ║
║                                              ║
║  [q] 退出                                     ║
╚══════════════════════════════════════════════╝
```

教师可以：
| 功能 | 说明 |
|------|------|
| **系统配置** | 开关solution可见性、切换解锁模式(自动/手动)、调整提示等级 |
| **学生进度管理** | 查看任一学生详细进度、手动解锁/锁定实验、重置单个学生 |
| **快速演示** | 不经过解锁限制，直接打开任意实验的任意步骤，用于课堂演示 |
| **教学统计** | 每个实验每步的平均耗时、学生最常按 `h` 的步骤（即教学难点） |
| **一键重置** | 新学期开始时重置所有学生进度 |
| **进入学生模式** | 教师自己以学生身份体验一遍，进度不影响真实学生 |

配置存储在 `.teacher-config` 文件中：
```bash
# .teacher-config
SOLUTION_ENABLED=false      # 学生能否直接看答案
AUTO_UNLOCK=true            # 完成一个实验自动解锁下一个
HINT_LEVEL=2               # 1=只给方向, 2=给具体线索(默认), 3=直接给答案
MAX_STUDENTS=30
```

## 四、核心技术组件

### 4.1 `lib/guide-framework.sh` — 渐进引导框架

```bash
# 框架提供的函数：
guide_init "Lab 04" "SQL注入"          # 初始化：设置标题
guide_step "01-background"             # 加载并显示一个步骤
guide_check "check-02.sh"             # 运行验证脚本
guide_hint "04"                        # 显示提示（渐进式：hint1→hint2→solution）
guide_mark_complete "step-id"          # 标记步骤完成
guide_get_next_unread                  # 获取下一个未读步骤
guide_is_lab_complete                  # 检查整个实验是否完成
guide_show_progress                    # 显示步骤进度条
```

## 七、关键设计决策

### 7.1 为什么用 Bash 而不是 Python？
- 学生在 Kali 中已经习惯终端操作
- 框架需要和学生执行的命令（curl、nmap、jq）无缝衔接
- 零依赖，不需要额外安装
- 彩色输出的终端体验更直接

### 7.2 解锁机制
- **默认模式（auto_unlock=true）**：完成一个实验自动解锁下一个
- **自由模式（auto_unlock=false）**：教师手动控制解锁（适合跳过某些实验）
- 进度存在 `.progress/` 目录，教师可通过 `progress.sh --reset student` 重置

### 7.3 Hint 渐进式
- 学生卡住时按 `h` 获取提示
- 提示分 3 级：`hint1`（方向指引）→ `hint2`（具体线索）→ `solution`（完整答案）
- 教师可配置 `solution_enabled=false` 禁止学生直接看答案

### 7.4 向后兼容
- 原有 `README.md` 保留为"实验概览"
- 原有 `start-lab.sh`、`reset-lab.sh` 不变
- 学生如果不想用渐进引导，仍可直接看 README
